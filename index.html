02 — CATEGORY ANALYSIS & PRODUCT IMPLICATIONS

Self-serve rate by category

WHAT THIS MEANS FOR COMPOSIO (STRATEGIC PRODUCT IMPLICATIONS)
A. BUILD THE OBVIOUS WINS

Prioritize high-value applications with broad APIs and self-serve credentials (GitHub, Stripe, Supabase, Linear, Notion, Firecrawl, Apify). These achieve instant toolkit coverage with zero credential friction.

B. PRODUCTIZE AUTH FRICTION

Transform recurring credential friction into reusable product infrastructure (guided OAuth setup, pre-configured application templates, and token assistance for Meta Ads, Google Ads, WhatsApp Business).

C. PARTNER AROUND COMMERCIAL GATES

Enterprise sales, partner approvals, and platform restrictions are access/BD problems, not engineering problems (DealCloud, PitchBook, Paygent Connect, Salesforce Commerce Cloud). Form dedicated outreach channels.

03 — STRATEGIC FOCUS

What Composio Should NOT Build

✕ DO NOT build custom engineering workarounds for enterprise commercial gates (DealCloud, PitchBook).
✕ DO NOT prioritize apps solely because they expose documented REST/GraphQL endpoints.
✕ DO NOT treat MCP availability as proof of API feasibility or credential readiness.
✕ DO NOT spend engineering effort equally across all 100 target applications.
"Instead: Build the obvious. Productize recurring friction. Partner around commercial walls."
04 — MCP EVALUATION SIGNAL
MCP = ACCELERATION LAYER, NOT ACCESS LAYER

MCP is an acceleration signal, not proof of API feasibility.

MCP can significantly reduce integration effort when credentials and API access are already available self-serve. However, MCP does not eliminate credential gating, enterprise approval, or commercial restrictions. Apps with MCP exhibit 89.2% readiness vs 68.6% for apps without MCP (+20.6% readiness delta) because modern developer platforms publish both.

07 — METHODOLOGY & SCORING

How we score buildability

Deterministic 0-to-100 scoring model across six research dimensions.

1. Public API Usability (25 pts)

REST, GraphQL, or gRPC available (25 pts); CLI wrapper (15 pts); No API (0 pts).

2. Credential Access (25 pts)

Self-serve (25 pts); Paid subscription (20 pts); Admin gated (10 pts); Partner/Sales (0 pts).

3. Auth Documentation (15 pts)

OAuth2/API Key docs with code samples (15 pts); Basic auth (10 pts); Ambiguous (5 pts).

4. API Surface Breadth (15 pts)

Broad CRUD + Webhooks (15 pts); Moderate capabilities (10 pts); Narrow single-endpoint (5 pts).

5. Documentation Quality (10 pts)

Interactive OpenAPI/Swagger portal (10 pts); Static markdown (7 pts); Fragmented (3 pts).

6. MCP Signal (10 pts)

Official MCP server published (10 pts); Community MCP available (7 pts); None found (0 pts).

Hard Blocker Override Rule: If an application is gated behind enterprise sales (contact_sales), partner vetting (partner_gated), or lacks a public API, its verdict is forcibly capped at Blocked regardless of documentation score.

          11 — RESEARCH LIMITATIONS
